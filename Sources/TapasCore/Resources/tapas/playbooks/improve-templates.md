# Improve my templates

Use when asked to suggest or make template improvements based on repeated requests
in saved dictations. Read the named library templates, or list available templates
and select those relevant to the request. Use the requested period, or the last
30 days if unspecified; state the dates and number of takes reviewed.

Look for repeated formatting instructions, requested sections, exclusions, and
explicit corrections. Link each proposed change to supporting recordings and the
template it would affect. A spoken instruction is evidence of a request, not proof
that an existing template was used or failed. Separate one-off needs from recurring
ones and explicit preferences from inference. Avoid expanding a template with
conflicting requirements from unrelated audiences or tasks; propose a variant
when that preserves a useful distinction.

Show the current behavior, proposed change, supporting evidence, and an illustrative
output outline. Do not fabricate meeting content to demonstrate a change. If there
is insufficient evidence, say so instead of manufacturing improvements.

When asked for recommendations, return proposals without editing. When asked to
apply changes, edit the requested Markdown files in the current library's
`templates/`, preserving unrelated customizations and summarizing the changes.
Create a separate variant for a new use case when appropriate. Do not edit bundled
app resources or installed SKILL.md copies. Save a separate analysis under
`outputs/` only when requested. No skill reinstall is needed after template edits.
